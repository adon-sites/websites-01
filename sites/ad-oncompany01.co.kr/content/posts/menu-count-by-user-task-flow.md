## 메뉴 개수에는 정해진 정답이 없습니다

홈페이지를 개편할 때 가장 먼저 나오는 질문은 상단 메뉴를 몇 개로 할지입니다. 다섯 개가 좋다거나 일곱 개를 넘기면 안 된다는 식의 숫자는 쉽게 퍼지지만, 실제로는 사이트마다 이용자가 하려는 일이 다르기 때문에 같은 숫자를 적용하기 어렵습니다.

메뉴가 많으면 사이트의 모든 내용을 보여 주는 것처럼 느껴져도 선택지가 늘어난 만큼 고르는 시간이 길어집니다. 반대로 항목을 지나치게 적게 묶으면 필요한 정보가 '서비스'나 '안내' 같은 넓은 이름 뒤에 숨어 버립니다. 그래서 개수 자체보다 각 메뉴가 어떤 과업으로 이어지는지를 먼저 살펴보는 편이 정확합니다.

## 항목마다 기대하는 내용을 한 문장으로 적어 봅니다

현재 메뉴를 종이에 모두 적고, 각 항목을 눌렀을 때 이용자가 기대할 내용을 한 문장으로 설명해 봅니다. 문장을 쓰기 어려운 항목은 이름이 모호하다는 신호일 수 있습니다. 서로 다른 두 메뉴가 같은 페이지로 이동한다면 중복일 가능성이 있으니 하나로 합칠지 검토합니다.

또 하나의 메뉴 안에 성격이 다른 정보가 많이 들어 있으면 이름만으로는 무엇이 나올지 알기 어렵습니다. 내부 조직도에 맞춰 만든 분류가 이용자의 질문 순서와 다른 경우도 흔합니다. 운영하는 사람에게는 자연스러운 구분이 처음 방문한 사람에게는 낯선 용어일 수 있다는 점을 염두에 둡니다.

## 처음 온 사람에게 과업을 주고 지켜봅니다

메뉴 구조가 맞는지는 처음 방문한 사람에게 구체적인 과업을 주고 어디를 누르는지 관찰하면 알 수 있습니다. 예를 들어 예약을 바꾸고 싶다는 과업을 줬는데 공지와 고객지원 사이에서 계속 망설인다면 두 메뉴의 경계를 다시 정해야 합니다.

이때 클릭 수만 세지 말고 잘못된 페이지로 들어갔다가 되돌아온 경로를 함께 봅니다. 담당자가 옆에서 힌트를 주면 실제 이용과 멀어지므로, 질문에는 답하지 않고 조용히 지켜보는 쪽이 정확한 결과를 줍니다. 한두 명의 관찰이라도 반복해서 막히는 지점이 보이면 개선의 출발점이 됩니다.

관찰 결과는 '어디가 불편했다'는 감상으로 남기기보다 어떤 과업에서 몇 번 되돌아갔는지, 어떤 메뉴 이름을 보고 어떤 내용을 기대했는지처럼 구체적인 문장으로 기록합니다. 이렇게 모은 기록은 메뉴 이름을 바꿀지, 항목을 합칠지, 위치만 옮길지를 정할 때 서로 다른 의견을 조율하는 기준이 됩니다.

## 모바일에서는 같은 메뉴가 다르게 작동합니다

데스크톱에서 한 줄로 보이던 메뉴는 모바일에서 접힌 목록으로 바뀝니다. 항목이 많을수록 스크롤 위치, 하위 메뉴가 펼쳐지는 방식, 닫기 버튼의 위치가 이용 행동에 영향을 줍니다. 화면을 확대했을 때 글자가 잘리거나 메뉴가 다른 버튼 위에 겹치는지도 직접 확인해야 합니다.

항목 수를 줄였더라도 모바일에서 꼭 필요한 메뉴가 아래로 밀려 보이지 않는다면 개선이라고 말하기 어렵습니다. 전화 연결이나 길찾기처럼 모바일에서 자주 쓰는 기능은 메뉴 안쪽에 묻히지 않았는지 따로 살핍니다.

기기와 화면 크기가 달라지면 같은 메뉴라도 손가락으로 누르기 쉬운 간격이 달라집니다. 항목 사이가 좁아 옆 메뉴가 눌리지는 않는지, 하위 메뉴를 닫지 않고 다른 화면으로 이동하면 어떻게 되는지도 한 번씩 시험해 보면 좋습니다.

## 이름과 주소를 바꿀 때는 연결된 안내를 함께 고칩니다

메뉴 이름을 바꾸면서 상세 페이지의 제목을 그대로 두면 이용자는 다른 내용을 열었다고 생각할 수 있습니다. 이름과 제목, 첫 문단이 같은 내용을 가리키는지 확인합니다. 주소가 달라졌다면 이전 주소에서 새 위치로 이어지는 경로를 두어 외부에서 걸어 둔 링크가 끊기지 않게 합니다.

공지나 안내 문서가 예전 메뉴 이름으로 위치를 설명하고 있다면 함께 수정합니다. 메뉴는 한 번 바꾸면 끝나는 작업이 아니라, 변경 이유와 결과를 기록하며 다듬는 작업입니다. 새 항목을 추가할 때는 무엇을 대신하고 어떤 질문을 해결하는지 먼저 설명할 수 있어야 합니다.

## 좋은 개수는 헤매지 않는 구조의 결과입니다

결국 적절한 메뉴 개수는 보기 좋게 맞춘 숫자가 아니라, 독자가 다른 메뉴를 헤매지 않고 목적지에 도달하는 구조에서 나옵니다. 과업 관찰과 모바일 확인, 연결 정보 점검을 거쳐 얻은 결과라면 항목이 여섯 개든 아홉 개든 충분히 근거가 있습니다.

메뉴를 손볼 때는 한 번에 크게 바꾸기보다 문제가 확인된 부분부터 조정하고, 바꾼 뒤 이용자의 이동이 나아졌는지 같은 방법으로 다시 확인합니다. 이런 점검이 쌓이면 메뉴는 운영하는 사람의 편의가 아니라 찾아오는 사람의 질문 순서를 따라가게 됩니다.
