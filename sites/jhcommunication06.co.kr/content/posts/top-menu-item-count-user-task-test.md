## 메뉴 개수는 숫자가 아니라 구조의 문제입니다
상단 메뉴에 항목을 많이 넣으면 사이트의 모든 내용을 보여 주는 것 같지만, 선택지가 많아질수록 방문자는 어디를 눌러야 할지 오래 망설이게 됩니다. 반대로 지나치게 적게 묶으면 필요한 정보가 모호한 이름 뒤로 숨습니다. 그래서 몇 개가 적당한지를 정해진 숫자로 말하기는 어렵고, 각 항목이 어떤 과업으로 이어지는지, 그리고 하위 화면에서 원하는 내용을 쉽게 찾는지를 기준으로 판단하는 것이 맞습니다.

## 현재 메뉴를 종이에 적고 한 문장씩 설명해 봅니다
먼저 현재 메뉴를 종이에 적고, 각 항목을 눌렀을 때 기대할 수 있는 내용을 한 문장으로 설명해 봅니다. 서로 다른 두 메뉴가 같은 페이지로 이동한다면 중복일 수 있습니다. 한 메뉴 안에 성격이 다른 정보가 지나치게 많이 들어가 있으면 이름만 보고는 목적을 알기 어렵습니다. 내부 조직도의 부서 순서대로 만든 구조가 방문자의 질문 순서와 맞지 않는 경우도 많으니 함께 확인합니다.

## 처음 온 사람에게 과업을 주고 관찰합니다
처음 방문하는 사람에게 "예약 변경 방법을 찾아보세요"처럼 구체적인 과업을 주고 어디를 누르는지 지켜봅니다. 공지와 고객지원 사이에서 계속 망설이거나 엉뚱한 페이지로 들어갔다가 되돌아온다면 메뉴의 경계를 다시 정할 신호입니다. 클릭 수만 세지 말고 잘못 들어갔다 나온 경로를 함께 봅니다.

이 테스트를 진행할 때 담당자가 옆에서 힌트를 주면 실제 이용 상황과 멀어집니다. 말없이 지켜보고, 막힌 지점만 기록하는 편이 정확합니다. 참여자가 서너 명만 되어도 공통으로 막히는 부분은 비교적 드러납니다.

## 모바일에서는 메뉴가 다른 모양이 됩니다
컴퓨터 화면에서 한 줄로 보이던 메뉴가 휴대전화에서는 접힌 목록으로 바뀝니다. 항목이 많을수록 스크롤 위치, 하위 메뉴가 펼쳐지는 방식, 닫기 버튼의 위치가 행동에 영향을 줍니다. 화면을 확대하거나 글자 크기를 키웠을 때 글자가 잘리지는 않는지, 메뉴가 버튼 위로 겹치지 않는지도 시험합니다. 항목 수를 줄였더라도 꼭 필요한 메뉴가 화면 아래로 밀려났다면 개선이라고 말하기 어렵습니다.

## 바꿀 때는 기존 주소와 안내 문구를 함께 점검합니다
메뉴 이름이나 위치를 바꿀 때는 기존 주소로 들어오는 외부 링크가 있는지 먼저 확인합니다. 이름만 바꾸고 상세 페이지의 제목은 그대로 두면 이용자는 다른 내용을 연 것으로 느낄 수 있습니다. 이동한 페이지에는 필요에 따라 이전 주소에서 새 위치로 이어지는 경로를 둡니다. 공지나 안내 문서에서 예전 메뉴 이름으로 설명하고 있다면 함께 고칩니다.

## 메뉴 이름을 정할 때 함께 보는 기준
항목 수만큼 이름도 중요합니다. 기관 내부에서 쓰는 용어보다 방문자가 검색할 때 쓰는 말에 가까운지 확인하고, 한 메뉴 이름이 두 가지 뜻으로 읽히지 않는지 봅니다. "자료실"이나 "기타"처럼 범위가 넓은 이름은 무엇이 들어 있는지 짐작하기 어려워 클릭을 망설이게 만듭니다. 이름을 바꾸기 전후로 같은 과업 테스트를 한 번 더 해 보면 개선 여부를 직접 확인할 수 있습니다. 메뉴 이름과 해당 페이지 제목, 그리고 검색 결과에 보이는 제목이 서로 크게 어긋나지 않도록 맞추는 것도 방문자의 혼란을 줄이는 좋은 방법입니다.

## 변경 이유를 기록하며 천천히 다듬습니다
상단 메뉴는 자주 바꾸기보다 변경 이유와 결과를 기록하며 조금씩 다듬는 편이 좋습니다. 새 항목을 추가하려 할 때는 무엇을 대신하고 어떤 질문을 해결하는지 먼저 설명할 수 있어야 합니다. 설명이 어렵다면 아직 메뉴로 올릴 때가 아닐 수 있습니다. 좋은 항목 수는 보기 좋게 맞춘 숫자가 아니라 독자가 다른 메뉴를 헤매지 않고 목적지에 닿는 구조에서 나옵니다.

정리가 끝난 메뉴는 다른 담당자나 외부 방문자에게 한 번 더 보여 주고 의견을 받아 보세요. 만든 사람에게는 당연한 이름이 처음 보는 사람에게는 낯설 수 있습니다. 테스트 결과와 수정 이유를 짧은 문서로 남겨 두면 나중에 메뉴를 다시 손볼 때 같은 시행착오를 줄일 수 있고, 새 담당자가 맡았을 때도 구조를 이해하기 쉽습니다.

개선 결과는 한 번의 테스트로 단정하지 말고, 일정 기간이 지난 뒤 같은 방식으로 다시 확인합니다. 방문자가 많이 찾는 과업이 바뀌는 시기에는 메뉴 구조도 함께 점검해야 합니다.
