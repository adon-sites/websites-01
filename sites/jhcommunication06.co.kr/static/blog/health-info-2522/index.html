수정 날짜는 바뀐 항목과 확인 범위를 함께 남깁니다

수정 날짜 한 줄만 바꾸면 독자는 글 전체가 그날 새로 검토됐다고 받아들일 수 있습니다. 실제로는 연락처만 고쳤거나 문장 순서만 바꿨을 수 있습니다. 날짜와 함께 변경 항목과 확인 범위를 짧게 남겨야 합니다.

수정 기록은 ‘무엇을-왜-어떤 근거로-언제’ 바꿨는지 적습니다. 운영시간처럼 변동 가능성이 큰 정보는 공식 자료 확인일을 표시하고, 단순 오탈자 교정은 내용 검토와 구분합니다. 여러 사람이 고쳤다면 최종 승인자를 내부 기록에 연결합니다.

글 상단이나 하단의 공개 표시에는 독자에게 필요한 수준만 제공합니다. 지나치게 긴 내부 이력을 모두 보이기보다 현재 정보의 기준 시점과 중요한 변경을 알립니다. 과거 버전을 조용히 삭제해 언제 조건이 달라졌는지 모르게 하지 않습니다. 의료 정보의 근거가 바뀌었다면 해당 문단과 출처를 다시 검토합니다.

검색 결과나 공유 화면의 날짜가 자동으로 변경되는 시스템인지 확인합니다. 사소한 편집이 새 글처럼 노출되면 별도 검토일 필드를 사용하는 방안을 고려합니다. 외부 화면의 반영 시점은 사이트 저장 상태와 분리합니다.

완료된 수정 기록은 다음 담당자가 같은 자료를 다시 조사하지 않고 어느 항목을 재검토해야 하는지 알게 합니다. 날짜는 최신성 장식이 아니라 변경 범위를 추적하는 표지입니다.

수정 이력을 공개할 때 개인정보나 내부 보안 정보를 포함하지 않습니다. 담당자 실명 대신 검토 주체와 범위만 보여 줄 수 있으며 상세 기록은 승인된 내부 위치에 둡니다.

내용이 크게 바뀌어 과거 댓글이나 인용이 현재 문맥과 어긋난다면 해당 연결도 검토합니다. 본문 날짜만 바꾸고 주변 대화를 그대로 두지 않습니다.

수정 날짜와 함께 다음 검토 조건을 내부에 둡니다. 고정 주기 외에도 운영시간 변경, 새 공식 자료 발표, 주소 이전처럼 특정 사건이 생기면 즉시 재검토하도록 합니다.

최종 검토자는 수정 날짜는 바뀐 항목과 확인 범위를 함께 남깁니다 작업 전후의 차이를 처음 보는 이용자 관점에서 설명합니다. ‘수정 날짜는 바뀐 항목과 확인 범위를 함께 남깁니다’ 표현이 좋아졌다는 평가보다 잘못된 선택이나 추가 탐색이 줄었는지를 근거로 남깁니다.
