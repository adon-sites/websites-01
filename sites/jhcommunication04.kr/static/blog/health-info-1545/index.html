카페 글을 휴대전화로 읽는 이용자는 처음부터 끝까지 순서대로 보기보다 소제목을 빠르게 훑는 경우가 많습니다. 이때 모든 소제목이 비슷한 표현이거나 앞 문단을 읽어야 뜻이 통하면 각 부분이 맡은 답을 찾기 어렵습니다.

검수할 때 본문을 잠시 가리고 소제목만 세로로 읽습니다. 대상, 조건, 행동 가운데 무엇을 알려 주는 구간인지 예상할 수 없는 제목은 넓은 표현을 줄이고 구체적인 질문 단위로 고칩니다. 다만 검색어를 반복하려고 사실 범위를 바꾸지는 않습니다.

다음으로 폭이 작은 화면에서 소제목 바로 아래 첫 문장을 확인합니다. 제목이 예고한 답이 멀리 떨어져 있으면 배경 설명을 줄이거나 답을 앞으로 옮깁니다. 한 구간에 두 질문이 섞였다면 문단을 자르는 것보다 먼저 역할을 나눌지 결정합니다.

완성 뒤에는 특정 소제목에서 들어온 독자가 그 부분만 읽고도 필요한 다음 행동을 알 수 있는지 시험합니다. 관련 정보가 다른 페이지에 있다면 막연한 링크 대신 이동 이유를 붙입니다. 독자는 화면을 여러 번 왕복하지 않고 필요한 구간을 골라 읽을 수 있어야 하며, 이것이 소제목 독립성을 판단하는 기준입니다.

소제목 사이의 위계도 함께 봐야 합니다. 같은 단계의 제목이 질문과 결론처럼 서로 다른 역할을 갖고 있으면 글의 구조를 오해할 수 있으므로 상위 질문과 하위 확인 항목을 구분합니다. 제목만 모아 읽었을 때 논리 순서가 보이되, 앞 제목의 문장을 그대로 이어야 이해되는 형태는 피합니다. 검수자는 원하는 답을 찾는 데 멈춘 화면 수와 잘못 선택한 구간을 메모해 다음 편집의 근거로 씁니다. 특히 마지막 소제목은 앞부분의 반복 요약보다 독자가 실행할 확인 순서를 스스로 이해하게 해야 합니다.
