현재 상태를 설명할 근거부터 모은다: 현재 색인·속도·모바일·구조·콘텐츠 상태에 대한 진단 근거를 요청한다. 작업별 파일·페이지·보고서, 담당자, 권한, 외주 여부와 유지 비용을 확인한다.

“제안된 작업은 사이트의 어떤 확인된 문제를 해결하고 완료를 어떻게 검증하는가”를 다루는 문장은 사실, 개인별 판단, 아직 모르는 내용으로 나눠 읽는다. “제안된 작업은 사이트의 어떤 확인된 문제를 해결하고 완료를 어떻게 검증하는가”의 사실에는 작성자와 시점을 붙이고 개인별 판단은 자격 있는 담당자의 설명을 기록한다. “제안된 작업은 사이트의 어떤 확인된 문제를 해결하고 완료를 어떻게 검증하는가”의 미확인 항목이 선택을 바꿀 수 있다면 결론보다 추가 확인을 먼저 배정한다.

모은 정보는 “제안된 작업은 사이트의 어떤 확인된 문제를 해결하고 완료를 어떻게 검증하는가”의 판단 순서에 맞춰 사용한다: 목표 질문과 페이지를 정하고 기술·콘텐츠·측정 작업을 단계로 나눈다. 변경 전 백업, 승인, 배포, 오류 대응, 계약 종료 시 계정·소스·데이터 인계를 합의한다.

다음 정보는 결론의 근거로 삼기 어렵다: 특정 순위와 기간 보장, 출처 불명 링크, 숨은 문구, 대량 복제 페이지, 업체 계정에만 남는 자산을 경계한다. 사례 결과를 동일하게 재현된다고 보지 않는다.

최종 결정을 내리기 전에는 “제안된 작업은 사이트의 어떤 확인된 문제를 해결하고 완료를 어떻게 검증하는가”를 처음 적었을 때와 지금 확보한 답을 비교한다. 설명이 달라졌다면 바뀐 근거와 날짜를 진단 근거·작업·산출물·권한·검수·인계를 담은 홈페이지 개선 제안표에 추가하고, 결론에 영향을 주지 않은 참고 정보는 별도 칸으로 옮긴다. 다른 검토자도 “제안된 작업은 사이트의 어떤 확인된 문제를 해결하고 완료를 어떻게 검증하는가”에 관해 확인된 내용과 추가로 물을 부분을 구분할 수 있어야 한다.

정리 결과는 진단 근거·작업·산출물·권한·검수·인계를 담은 홈페이지 개선 제안표에 남긴다. 진단 근거·작업·산출물·권한·검수·인계를 담은 홈페이지 개선 제안표에는 “제안된 작업은 사이트의 어떤 확인된 문제를 해결하고 완료를 어떻게 검증하는가”의 근거가 된 자료, 작성 시점, 확인한 담당자와 다음 확인일을 적는다. 진단 근거·작업·산출물·권한·검수·인계를 담은 홈페이지 개선 제안표에서 개인 정보가 포함된 원본은 공개용 메모와 분리해 보관한다.

마지막 점검은 다음 기준으로 한다: 확인된 문제와 작업이 연결되고 사이트 소유자가 변경을 통제하며 정책에 맞는 측정·인계 계획이 있으면 진행 여부를 결정한다.
