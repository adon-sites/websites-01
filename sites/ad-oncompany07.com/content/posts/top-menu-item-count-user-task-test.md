## 적절한 개수는 숫자가 아니라 과업에서 나옵니다

상단 메뉴에 항목이 많으면 사이트의 모든 내용을 보여 주는 듯하지만 선택은 오히려 어려워집니다. 반대로 항목을 지나치게 묶으면 필요한 정보가 모호한 이름 뒤로 숨습니다. 다섯 개가 좋다거나 일곱 개를 넘기지 말라는 식의 숫자는 참고일 뿐, 우리 사이트의 이용자에게 맞는 개수는 따로 확인해야 합니다.

기준은 각 메뉴가 어떤 과업으로 이어지는지, 그리고 하위 화면에서 목적지를 찾기 쉬운지입니다. 예약, 위치 확인, 소식 보기처럼 이용자가 실제로 하려는 일을 나열하고, 그 일마다 가장 짧은 길이 있는지 살펴봅니다.

## 항목마다 기대 내용을 한 문장으로 적어 봅니다

현재 메뉴를 종이에 적고, 각 항목을 눌렀을 때 기대되는 내용을 한 문장으로 설명해 봅니다. 서로 다른 두 메뉴가 같은 페이지로 연결된다면 중복일 가능성이 큽니다. 한 메뉴 안에 성격이 다른 정보가 많이 섞여 있으면 이름만으로는 목적을 알기 어렵습니다.

내부 조직도에 맞춰 만든 분류가 이용자의 질문 순서와 어긋나는 경우도 흔합니다. 운영하는 사람이 보기 편한 분류와 찾는 사람이 떠올리는 분류는 다를 수 있으므로, 이용자가 쓰는 말로 이름을 붙였는지 다시 읽어 봅니다.

## 처음 온 사람에게 과업을 주고 지켜봅니다

사이트를 처음 보는 사람에게 예약 변경 방법 찾기 같은 구체적인 과업을 주고 어디를 누르는지 관찰합니다. 공지와 고객지원 사이에서 계속 망설이는 모습이 보인다면 두 메뉴의 경계를 다시 정해야 한다는 신호입니다.

클릭 수만 세지 말고 잘못된 페이지로 들어갔다가 되돌아온 경로를 눈여겨봅니다. 시험하는 동안 담당자가 옆에서 힌트를 주면 실제 사용 환경과 멀어지므로, 말없이 지켜보고 막힌 지점만 기록하는 편이 정확합니다. 서너 명만 관찰해도 반복되는 막힘은 쉽게 드러납니다.

## 모바일에서는 같은 메뉴가 다른 모양이 됩니다

데스크톱에서 한 줄로 보이던 메뉴는 휴대전화에서 접힌 목록으로 바뀝니다. 항목이 많아지면 스크롤 위치, 하위 메뉴가 펼쳐지는 방식, 닫기 버튼의 위치가 이용 행동에 직접 영향을 줍니다. 화면을 확대했을 때 글자가 잘리거나 메뉴가 다른 버튼 위에 겹치지 않는지도 확인합니다.

데스크톱에서 항목 수를 줄였더라도 모바일에서 꼭 필요한 메뉴가 아래로 밀려 보이지 않는다면 개선이라고 할 수 없습니다. 실제 휴대전화로 가장 중요한 과업 세 가지를 직접 해 보는 시험을 발행 전 필수 절차로 두면 좋습니다.

## 이름과 주소를 바꿀 때의 영향을 미리 살핍니다

메뉴를 바꿀 때는 기존 메뉴 주소와 외부에서 걸린 링크를 먼저 점검합니다. 이름만 바꾸고 상세 페이지의 제목은 그대로 두면 이용자는 다른 내용을 연 것으로 생각할 수 있습니다. 위치가 옮겨진 페이지에는 이전 주소에서 새 주소로 안내되는 경로를 두어 길을 잃지 않게 합니다.

공지나 문서에서 예전 메뉴 이름을 설명하고 있다면 함께 수정합니다. 상담 직원이 이용자에게 알려 주는 말도 새 이름으로 바꾸어야 안내가 어긋나지 않습니다.

## 변경 이유와 결과를 기록하며 다듬습니다

상단 메뉴는 자주 바꾸기보다 변경한 이유와 결과를 기록하면서 조금씩 다듬는 편이 좋습니다. 새 항목을 추가하려면 무엇을 대신하는지, 어떤 질문을 해결하는지부터 설명해야 합니다.

좋은 항목 수는 보기 좋게 맞춘 숫자가 아니라, 이용자가 다른 메뉴를 헤매지 않고 목적지에 도달하는 구조에서 정해집니다. 변경 뒤에는 같은 과업 시험을 한 번 더 해서 이전보다 막히는 지점이 줄었는지 비교해 봅니다. 결과가 나아지지 않았다면 되돌릴 수 있도록 이전 구성을 보관해 두는 것도 잊지 않습니다.

## 메뉴 점검에 쓰는 한 장짜리 기록 양식

시험 결과는 간단한 표로 남기면 비교가 쉽습니다. 과업, 처음 누른 메뉴, 목적지에 도달한 시간, 되돌아온 횟수, 관찰자 메모를 한 줄에 적습니다. 같은 양식을 변경 전후에 쓰면 어떤 항목이 실제로 길찾기를 도왔는지 근거가 생깁니다.

메뉴 이름이 헷갈린다는 의견이 나오면 후보 이름을 두세 개 적어 다시 시험해 봅니다. 담당자의 취향으로 결정하지 않고 이용자가 목적지를 맞히는 비율로 판단하면 논쟁이 줄어듭니다. 기록은 다음 개편 때 처음부터 다시 시험하지 않아도 되는 자산이 됩니다.
