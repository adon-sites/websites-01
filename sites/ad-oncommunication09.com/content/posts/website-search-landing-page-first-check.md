## 순위표를 보기 전에 검색자가 도착한 화면부터

웹사이트의 검색 대응을 맡기려는 사람이 가장 많이 묻는 말은 몇 위까지 올릴 수 있느냐입니다. 그런데 순위는 검색 서비스와 경쟁 사이트에 따라 달라지는 값이어서 약속하기 어렵고, 순위만 바라보면 정작 확인해야 할 것을 놓칩니다. 검색한 사람이 클릭해서 도착한 페이지가 그가 찾던 내용을 담고 있는지가 먼저입니다.

예를 들어 특정 서비스 이름을 검색한 사람이 해당 서비스 설명 대신 회사의 일반 소개만 만난다면 검색어와 페이지가 어긋난 것입니다. 이런 상태에서는 순위가 올라가도 문의로 이어지기 어렵습니다.

## 페이지마다 맡은 질문이 있는지 목록으로 만들기

점검의 시작은 사이트의 모든 페이지를 한 줄씩 적어 두고, 각 페이지가 어떤 질문에 답하는지 옆에 쓰는 일입니다. 메인 페이지는 업체가 하는 일과 위치, 문의 방법을 보여 주고, 세부 페이지는 서비스 범위와 이용 절차를 설명합니다. 요금에 관한 질문은 어떤 항목이 포함되고 무엇에 따라 달라지는지를 설명하는 방식이 정확합니다.

답하는 질문을 한 줄로 쓰기 어려운 페이지나, 서로 같은 질문을 쓴 페이지가 보이면 정리 대상입니다. 같은 내용을 제목만 바꿔 여러 곳에 두었다면 하나로 합치거나 실제로 다른 질문을 다루도록 고치세요.

## 지역을 말할 때는 실제 사업장 기준으로

지역 검색을 의식한다면 실제 사업장의 위치와 서비스가 닿는 범위에 맞춰 표현해야 합니다. 여러 지역 이름을 한꺼번에 늘어놓아 지점이 많은 것처럼 보이게 하면 방문자에게도 검색 서비스에도 혼란을 줍니다. 찾아오는 방식인지, 직접 방문하는 방식인지, 온라인으로도 진행되는지를 분명히 적고, 지도 서비스의 주소와 시간이 홈페이지와 같은지 확인합니다.

범위 밖의 지역에서 온 문의를 성과처럼 부풀려 보고하는 것도 경계할 일입니다. 제공하지 않는 지역의 문의가 많다면 페이지의 안내가 모호하다는 신호로 읽을 수 있습니다.

## 직접 눌러 보며 확인하는 기술적 항목

주요 페이지가 정상적으로 열리는지, 휴대전화에서 메뉴와 버튼이 잘 작동하는지, 이미 사라진 페이지로 가는 링크가 남아 있지는 않은지 직접 눌러서 확인합니다. 제목은 페이지가 다루는 핵심 질문과 맞추고, 첫 문단에서 곧바로 답을 제시하는 것이 좋습니다.

수정한 날짜와 이유를 적어 두는 습관도 중요합니다. 기록 없이 여러 곳을 한꺼번에 고치면 나중에 유입이 달라졌을 때 어떤 수정 때문인지 알 방법이 없습니다.

확인할 때는 가능한 한 방문자와 비슷한 환경을 만들어 보세요. 로그인하지 않은 상태에서, 휴대전화의 모바일 데이터로, 처음 방문하는 사람처럼 사이트를 열어 보면 평소 보이지 않던 불편이 드러납니다. 이미지가 늦게 열리는 페이지나 팝업이 본문을 가리는 화면도 이때 발견됩니다.

발견한 문제는 심각도를 나누어 기록합니다. 문의 양식이 작동하지 않는 문제와 문구의 오탈자는 우선순위가 다르므로, 먼저 방문자가 길을 잃는 문제부터 고치는 순서를 정합니다.

## 실행 업체를 고를 때 물을 수 있는 질문

검색 대응을 외부에 맡길 때는 몇 편을 올리는지나 몇 위를 목표로 하는지보다, 현재 사이트의 오류를 어떻게 찾는지와 콘텐츠를 누가 고치는지를 물어보세요. 유입된 검색어와 실제 문의를 함께 보면서 빠진 설명을 채우는 운영 방식인지 확인하는 것이 좋습니다.

통합검색의 특정 위치를 확정해서 말하는 곳은 신중하게 봐야 합니다. 대신 이용자가 필요한 페이지에 도착하는지는 직접 시험하고 검증할 수 있고, 그 검증 방법을 설명해 주는 곳이 계약 후에도 이야기하기 쉽습니다.
