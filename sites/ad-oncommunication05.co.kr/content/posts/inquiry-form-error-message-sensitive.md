## 오류 화면이 입력한 내용을 그대로 보여 주면 왜 문제인가요?

양식에 건강 상태나 검사 결과를 적은 사람이라면 그 문장이 오류 화면에 다시 나타났을 때 곤란할 수 있습니다. 공용 기기에서 작성했거나 화면을 캡처해 두는 경우에는 다른 사람이 볼 수 있기 때문입니다. 병원 문의는 내용의 성격상 노출을 특히 조심해야 하는 경우가 많습니다.

오류 안내는 어디를 고쳐야 하는지만 알려 주면 충분합니다. 사용자가 쓴 민감한 문장을 불필요하게 되풀이하는 것은 안내의 목적과 맞지 않습니다.

## 오류 문구는 어떻게 써야 하나요?

해당 입력 칸 가까이에 무엇을 고쳐야 하는지를 짧게 씁니다. 예를 들어 전화번호 형식을 확인해 달라는 정도의 문장이면 됩니다. 사용자가 입력한 전체 문장을 메시지 제목이나 자동 회신에 복사하지 않도록 설정합니다.

온라인종합광고실행사와 협업할 때는 문구 초안을 받는 데서 끝내지 않고 실제 화면에서 어떻게 보이는지까지 확인합니다. 실패한 뒤 작성한 내용이 모두 사라지는 것도 반복 입력과 잘못된 제출을 부르므로 함께 살핍니다.

[표] 오류 상황별 문구 예시
| 상황 | 알려야 할 내용 | 피할 표현 |
| --- | --- | --- |
| 연락처 오류 | 형식을 다시 확인 | 입력한 번호 전체 반복 |
| 필수 칸 비어 있음 | 비어 있는 칸 위치 | 다른 칸의 내용 반복 |
| 첨부 실패 | 파일 형식과 크기 안내 | 파일명이나 내용 노출 |
| 전송 지연 | 접수 상태 확인 방법 | 증상 문장 재표시 |

## 양식에서 받는 항목은 어떻게 정하나요?

오류 문구를 고치기 전에 수집하는 항목부터 줄여 봅니다. 예약 가능한 시간만 묻는 양식에서 긴 증상 설명을 필수로 받는다면 문구가 아니라 수집 목적을 다시 검토해야 합니다.

자유 입력칸에는 의료 기록을 공개된 공간에 적지 않도록 안내합니다. 개별 판단이 필요한 내용은 의료진이나 전화 상담 같은 적절한 경로로 이어 줍니다. 꼭 필요한 항목만 받는 구조가 오류 화면에서 노출될 내용을 가장 확실하게 줄입니다. 항목을 줄이면 입력하는 사람의 부담도 함께 낮아집니다.

## 전송 상태와 중복 제출은 어떻게 구분하나요?

전송에 실패한 경우와 서버에는 접수됐지만 확인 문자가 늦는 경우를 화면에서 구분해 알려 줍니다. 구분되지 않으면 사용자가 같은 문의를 여러 번 보내고, 접수팀에는 중복 건이 쌓입니다.

중복 접수는 한 건으로 묶어 처리하고, 사용자가 자신의 접수 상태를 확인할 방법을 제공합니다. 접수 완료 화면에도 입력한 상담 내용은 요약해서 다시 보여 주지 않습니다. 처리 상태가 보이면 불안해서 다시 보내는 일도 줄어듭니다. 입력 내용을 유지하는 기능이 있다면 뒤로 가기나 공유 기기 사용 뒤에도 다른 사람에게 보이지 않는지 확인합니다.

## 검수와 로그는 어떻게 점검하나요?

빈칸, 잘못된 연락처, 첨부 실패, 정상 제출을 각각 시험합니다. 실제 환자 정보 대신 테스트용 자료를 쓰고, 끝난 뒤에는 삭제합니다.

[표] 점검 순서
| 순서 | 시험 내용 | 확인할 점 |
| --- | --- | --- |
| 1 | 빈칸 제출 | 위치 안내만 나오는지 |
| 2 | 잘못된 연락처 | 입력 내용이 반복되지 않는지 |
| 3 | 첨부 실패 | 원인 안내가 있는지 |
| 4 | 정상 제출 | 접수 확인과 중복 처리 |

오류 기록에도 사용자가 쓴 건강 정보 전체가 복사되어 남지 않는지 살핍니다. 문제를 찾는 데 필요한 상태 정보와 개인의 상담 내용은 분리해서 저장해야 합니다. 로그를 열람할 수 있는 사람의 범위도 필요한 담당자로 제한하고, 보관 기간을 정해 두면 노출 가능성을 더 줄일 수 있습니다. 오류 화면도 방문자의 정보를 다루는 공개 안내라는 관점으로 확인합니다. 이 점검은 양식을 고칠 때마다 반복하는 것이 좋습니다. 점검 결과는 날짜와 함께 기록해 두어 다음 수정 때 비교할 수 있게 합니다.

## 자주 묻는 질문

### 오류 문구에 사용자의 입력을 일부만 보여 줘도 되나요?

피하는 편이 안전합니다. 어느 칸을 고쳐야 하는지만 알려 주면 충분하고, 입력한 내용은 보여 주지 않아도 됩니다.

### 온라인종합광고실행사에 양식 수정을 맡길 때 무엇을 요청해야 하나요?

오류 문구와 자동 회신, 접수 확인 화면에서 입력 내용이 반복되지 않는지 확인해 달라고 요청합니다. 테스트 결과도 함께 받아 두면 좋습니다.

### 입력 내용이 사라지지 않게 하면 오히려 위험하지 않나요?

공용 기기에서는 위험할 수 있습니다. 재입력 부담과 개인정보 보호를 함께 보고, 완료 뒤에는 화면에 남지 않게 정합니다.

### 시험할 때 실제 환자 정보를 써도 되나요?

쓰지 않습니다. 가상의 테스트 자료를 사용하고 시험이 끝나면 접수된 기록도 함께 삭제합니다.

### 오류 기록은 얼마나 자세히 남겨야 하나요?

문제를 찾는 데 필요한 상태 정보만 남깁니다. 사용자가 쓴 상담 문장은 기록에 복사되지 않도록 분리합니다.

### 접수 확인 문자가 늦으면 어떻게 안내하나요?

접수는 되었으나 문자가 지연될 수 있다는 점과 상태를 확인할 방법을 함께 알립니다. 같은 문의를 다시 보내지 않도록 안내합니다.
