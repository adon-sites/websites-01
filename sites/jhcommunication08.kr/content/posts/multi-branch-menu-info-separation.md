## 같은 이름의 버튼이 여러 곳을 가리킬 때 생기는 문제
장소가 여러 곳인 사이트에서 메뉴가 모두 같은 이름으로 되어 있으면 이용자는 지금 보고 있는 시간표가 어느 장소의 것인지 확신하기 어렵습니다. 화면 위쪽에는 대표 번호가 하나 보이는데 실제 상담은 장소마다 따로 운영된다면, 전화를 건 사람이 엉뚱한 곳으로 연결되는 일도 생깁니다.

따라서 메뉴를 나누는 이유는 보여 줄 이름을 늘리기 위해서가 아닙니다. 이용자가 한 장소를 고른 순간부터 문의를 마칠 때까지, 다른 장소의 정보가 섞이지 않게 하려는 것입니다. 설계 회의에서는 이 흐름을 끝에서 끝까지 한 번에 따라가 보는 시간을 따로 잡는 것이 좋습니다.

## 장소별 기본 정보를 하나의 표로 관리합니다
먼저 현재 운영 중인 장소만 목록에 남아 있는지 확인합니다. 이미 닫았거나 옮긴 곳이 그대로 있으면 찾아간 사람이 헛걸음을 합니다. 그다음 장소마다 주소, 공식 연락처, 운영 시간, 제공하는 서비스 범위를 한 표에 모읍니다.

표를 기준으로 삼으면 한 장소의 내용이 바뀌었을 때 고쳐야 할 화면이 어디인지 찾기 쉽습니다. 특정 장소에서만 되는 서비스는 표에 조건으로 적고, 화면에서도 모든 장소에 해당하는 것처럼 읽히지 않게 표시합니다. 주차나 예약 가능 여부처럼 확인하지 못한 항목을 다른 장소의 내용으로 채우는 일은 하지 않습니다.

## 세 가지 진입 상황을 직접 따라가 봅니다
이용자가 사이트에 들어오는 길은 하나가 아닙니다. 홈 화면에서 장소를 고르는 경우, 검색 결과에서 특정 장소 페이지로 바로 들어오는 경우, 예전에 저장해 둔 링크로 예약 화면에 들어오는 경우를 나누어 시험해 봅니다.

각 경우에 첫 화면만 보고도 지금 어느 장소인지 알 수 있는지, 이어지는 안내와 예약 화면이 같은 장소를 유지하는지 확인합니다. 선택이 풀려 처음 지정된 장소로 돌아가거나 하단에 다른 장소의 번호가 남아 있다면 바로 고쳐야 할 문제입니다. 홈 화면을 거치지 않은 방문자도 맥락을 잃지 않는 구조가 기본입니다.

## 작은 화면에서는 선택 상태를 눈에 보이게 둡니다
스마트폰에서는 장소 선택 메뉴가 접힌 형태로 제공되는 경우가 많아, 지금 무엇이 선택되어 있는지 놓치기 쉽습니다. 선택한 장소의 이름을 화면 위쪽에 글자로 보여 주고, 다른 장소로 바꾸는 방법을 가까이에 둡니다.

지도로 연결되는 버튼은 장소별로 정확한 주소를 열어야 하며, 이용자가 어디서 출발하든 같은 도착지를 가리키는지 눌러서 확인합니다. 장소 이름이 이미지 속에만 있으면 화면 읽기 도구를 쓰는 사람은 알 수 없으므로 글자로도 제공합니다. 같은 장소를 부르는 별칭이 화면마다 다르면 서로 다른 곳으로 오해하게 되니 하나로 통일합니다.

## 공통 안내와 장소별 조건이 어긋나지 않도록 관리합니다
공지나 자주 묻는 질문에는 장소마다 다른 조건이 섞여 들어가기 쉽습니다. 새 장소가 생기거나 한 곳의 운영 방식이 바뀌면 공통 문장이 여전히 모든 장소에 맞는지 다시 읽어 봅니다. 바꾼 날짜와 승인한 담당자를 기록해 두면 예전 값이 다시 올라오는 사고를 줄일 수 있습니다.

원하는 장소가 아님을 알아챈 이용자가 곧바로 다른 곳으로 바꿀 수 있는 버튼도 중요합니다. 처음부터 다시 찾아야 하는 수고를 덜어 주면 이탈이 줄어듭니다.

새 장소를 열거나 기존 장소를 닫을 때에는 메뉴뿐 아니라 검색에 노출되는 소개 문구, 지도 서비스의 표기, 안내 문자에 들어가는 링크까지 함께 정리해야 합니다. 사이트 안만 고치고 바깥의 정보가 그대로 남으면 이용자는 두 가지 서로 다른 안내를 접하게 됩니다. 변경 전후로 어느 채널을 점검했는지 기록해 두면 이후 누락을 추적하기 쉽습니다. 점검 주기는 분기마다 한 번처럼 일정하게 정하면 담당자가 바뀌어도 이어 가기 쉽습니다.

## 실무에서 확인할 점
처음 방문하는 사람 한두 명에게 원하는 장소를 고른 뒤 연락처와 운영 시간을 찾아 보게 하면 구분이 충분한지 금세 드러납니다. 변경 요청이 들어왔을 때 어느 화면까지 고쳐야 하는지 체크리스트로 관리하면 누락이 줄고, 담당자가 바뀌어도 같은 기준으로 이어서 점검할 수 있습니다. 메뉴 구성의 좋고 나쁨은 버튼 배열보다 이용자가 선택한 장소의 정보를 끝까지 확인할 수 있느냐에서 갈립니다.
