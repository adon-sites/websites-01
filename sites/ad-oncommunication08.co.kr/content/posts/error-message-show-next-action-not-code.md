## 코드만 보이는 화면에서 이용자는 멈춥니다

예약 양식을 제출했더니 영문과 숫자로 된 코드만 나타났다고 생각해 보세요. 이용자는 입력을 고쳐야 하는지, 잠시 뒤 다시 시도해야 하는지, 이미 접수가 끝난 것인지 알 방법이 없습니다. 내부 코드는 담당자가 원인을 찾을 때 도움이 되지만, 이용자에게 하나뿐인 안내가 되어서는 곤란합니다.

오류 메시지가 해야 할 일은 문제가 어디에 있는지, 지금 무엇을 하면 되는지를 알려 주는 것입니다. 이 두 가지가 담겨 있으면 코드가 함께 보이더라도 이용자는 다음 행동을 정할 수 있습니다.

## 입력 오류와 서비스 장애는 다르게 말합니다

먼저 이용자가 고칠 수 있는 오류와 서비스 쪽 문제를 구분합니다. 필수 항목이 비었다면 어느 항목인지 표시하고, 이미 입력한 다른 값은 지워지지 않게 유지해야 합니다. 같은 내용을 처음부터 다시 쓰게 만들면 이용자는 제출을 포기하기 쉽습니다.

반대로 서버나 외부 인증처럼 서비스 쪽에 문제가 있다면 이용자가 잘못한 것처럼 보이는 문구는 피합니다. 잠시 뒤에 다시 시도하거나 공식 문의 경로를 확인하도록 안내하되, 확인되지 않은 복구 시간을 약속하지는 않습니다.

## 결제와 예약에서는 완료 여부를 먼저 알려 줍니다

결제나 예약처럼 중요한 행동에서는 처리가 끝났는지가 가장 궁금한 정보입니다. 오류 화면이 나타나도 실제로는 접수가 이루어졌을 수 있는데, 확인 없이 다시 제출하라고 안내하면 중복 신청이 생길 수 있습니다.

따라서 현재 상태를 확인할 수 있는 경로를 함께 제공합니다. 운영자가 추가로 확인해야 한다면 필요한 정보를 최소한으로만 요청하고, 개인정보를 공개된 댓글이나 게시판에 남기게 하는 안내는 하지 않습니다.

## 메시지가 놓이는 위치와 전달 방식

문구뿐 아니라 위치도 중요합니다. 화면 맨 위에 오류라는 말만 보이고 문제가 된 입력란은 아래쪽에 있다면 찾기 어렵습니다. 해당 항목 가까이에 이유를 설명하고, 키보드 이동이나 화면 읽기 프로그램에도 오류가 전달되는지 확인하세요.

색깔만으로 오류 상태를 구분하는 것도 피합니다. 붉은색 테두리와 함께 글자로 된 설명이 있어야 색을 구별하기 어려운 이용자도 문제를 알아차릴 수 있습니다.

## 이용자용 문구와 내부 기록을 분리합니다

고객에게 보이는 문구와 내부 로그는 역할이 다르므로 분리하는 편이 좋습니다. 지원 담당자가 추적할 수 있도록 접수 번호나 발생 시각을 남기되, 시스템의 민감한 정보가 공개 화면에 드러나지 않게 주의합니다.

이용자가 오류 상황을 설명하려고 화면 전체나 민감한 입력값을 캡처해서 보내야 하는 구조도 바람직하지 않습니다. 문의할 때 필요한 번호만 알려 주면 되도록 안내하면 이용자도 운영자도 부담이 줄어듭니다.

## 문구를 고친 뒤 실제로 시험하기

문구를 바꾼 뒤에는 모바일과 컴퓨터에서 실제로 오류를 일으켜 보며 메시지와 시스템 동작이 일치하는지 확인합니다. 메시지는 다시 시도하라고 하는데 같은 동작이 계속 실패한다면 문구를 고쳐도 소용이 없습니다.

같은 오류가 반복된다면 문구를 더 친절하게 바꾸는 데서 멈추지 말고 원인을 해결해야 합니다. 좋은 오류 메시지는 이용자가 코드를 해독하게 만들지 않고, 자신의 작업이 어떤 상태인지 이해한 채 안전한 다음 단계를 고르도록 돕습니다.

## 메시지 문구를 쓸 때 참고할 구성

실제 문구는 세 부분으로 나누어 쓰면 읽기 쉽습니다. 첫 문장은 무슨 일이 일어났는지, 둘째 문장은 이용자가 지금 할 수 있는 행동, 셋째 문장은 해결되지 않을 때의 문의 경로를 담습니다. 예를 들어 이름 입력란이 비어 있다면 해당 칸 옆에 이름을 입력해 주세요라고 바로 알려 주는 식입니다.

문장은 짧게 쓰고 이용자를 탓하는 어조는 피합니다. 전문 용어나 내부 시스템 이름은 이용자가 알아볼 수 없으므로 일상의 말로 바꿉니다. 문구를 정할 때는 담당자끼리만 확인하지 말고, 서비스를 처음 쓰는 사람에게 화면을 보여 주고 무엇을 해야 하는지 말해 보게 하면 부족한 부분이 금방 드러납니다. 서비스마다 구조가 다르므로 위 구성은 상황에 맞게 조정해서 쓰시면 됩니다.

문구를 바꾼 날짜와 이후 문의 내용의 변화를 함께 적어 두면, 어떤 표현이 이용자에게 도움이 되었는지 나중에 판단하는 근거가 됩니다.
