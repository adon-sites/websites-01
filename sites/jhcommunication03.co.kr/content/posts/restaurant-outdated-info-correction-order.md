## 잘못된 정보가 퍼졌을 때 가장 먼저 할 일은 무엇인가요?

현재 사실을 확인하는 일입니다. 매장 주소, 영업시간, 쉬는 날, 메뉴, 예약 방식 가운데 무엇이 바뀌었는지 담당자가 문서 하나에 정리합니다. 이 문서가 이후 모든 수정의 기준이 됩니다. 문서에는 언제부터 바뀐 내용인지도 함께 적습니다. 적용 시점이 빠지면 고치는 사람마다 다른 날짜를 떠올려 수정이 또 엇갈립니다.

그다음 손님이 본 정보가 단순한 소문인지, 공식 채널에 남아 있는 오류인지 구별합니다. 이 구별이 되어야 무엇부터 고칠지 보입니다. 확인되지 않은 주장에는 감정적으로 맞서지 않고 정확한 공지를 내놓습니다.

## 직접 고칠 수 있는 곳과 없는 곳은 어떻게 나누나요?

직접 관리하는 지도 정보와 홈페이지, 예약 화면을 가장 먼저 고칩니다. 블로그에 남은 지난 행사나 예전 메뉴 글에는 끝난 날짜를 적거나 최신 안내로 가는 길을 덧붙입니다.

다른 사람이 올린 글은 마음대로 고칠 수 없습니다. 이럴 때는 공식 채널의 현재 정보를 쉽게 찾을 수 있게 하는 편이 현실적입니다. 플랫폼에 정정 요청 기능이 있다면 실제 오류와 근거를 확인한 뒤 이용합니다. 요청한 날짜와 내용을 적어 두면 반영 여부를 나중에 다시 확인하기 쉽습니다.

| 정보가 남은 곳 | 고칠 수 있는지 | 대응 |
| --- | --- | --- |
| 지도, 홈페이지, 예약 화면 | 직접 수정 가능 | 가장 먼저 현재 사실로 변경 |
| 직접 쓴 예전 블로그 글 | 직접 수정 가능 | 끝난 날짜 표시와 최신 안내 연결 |
| 다른 사람이 올린 글 | 직접 수정 불가 | 공식 안내를 찾기 쉽게 정비 |
| 플랫폼에 남은 오류 | 요청으로 가능 | 근거를 갖춰 정정 요청 |

## 온라인만 고치면 해결되나요?

그렇지 않습니다. 전화로는 쉬는 날이 맞다고 답하는데 현장 안내문에는 다른 날짜가 적혀 있다면, 온라인을 아무리 고쳐도 혼란이 남습니다. 응대하는 사람 모두가 같은 내용을 말해야 합니다. 출입문에 붙인 안내문과 계산대 옆 메모, 전화 자동 응답처럼 평소 눈에 익어 지나치기 쉬운 곳도 빠짐없이 살핍니다.

직원에게 바뀐 사실과 적용되는 시점을 공유합니다. 지점이 여러 곳이라면 어느 지점의 정보인지 표시해 다른 매장까지 잘못 이해되지 않게 합니다. 근무 교대가 잦은 매장이라면 구두로 전하는 데 그치지 않고 누구나 볼 수 있는 자리에 변경 내용을 적어 둡니다.

## 수정이 제대로 반영됐는지는 어떻게 확인하나요?

휴대전화로 검색 화면을 직접 열어 봅니다. 고치기 전과 고친 뒤의 화면을 기록해 두면 변경이 실제로 반영됐는지 비교할 수 있습니다. 메뉴가 바뀌었다면 그 내용도 함께 점검합니다. 다른 사람의 휴대전화나 로그인하지 않은 화면으로도 한 번 더 확인합니다.

같은 질문이 계속 들어오는지도 살핍니다. 손님이 자주 묻는 내용은 공식 안내의 첫 부분으로 올립니다. 종합광고대행사에 관리를 맡기고 있다면 수정 전후 기록을 받아 직접 대조합니다.

| 점검 항목 | 확인 방법 |
| --- | --- |
| 검색 화면 | 휴대전화에서 직접 검색 |
| 반영 여부 | 수정 전후 화면 기록 비교 |
| 반복 문의 | 같은 질문이 줄었는지 확인 |
| 현장 안내 | 온라인 정보와 날짜 대조 |

## 새 홍보 글은 언제 쓰는 것이 맞나요?

기존 오류를 고친 뒤입니다. 틀린 정보가 남아 있는 상태에서 새 글을 더하면 손님이 만나는 정보가 하나 더 늘어날 뿐입니다. 바로잡는 일의 기준은 게시물 수가 아니라 손님이 현재의 사실에 닿을 수 있는지입니다.

바깥에 있는 글을 모두 통제할 수는 없습니다. 그래도 매장이 책임지는 정보의 정확도는 높일 수 있습니다. 종합광고대행사와 다음 발행 계획을 세울 때 정정 작업이 끝났는지를 먼저 확인하고 순서를 정합니다. 정정이 끝난 뒤에 쓰는 글은 바뀐 내용을 알리는 공지부터 시작하는 것이 자연스럽습니다.

## 자주 묻는 질문

### 예전 블로그 글은 지우는 것이 좋나요?

꼭 지울 필요는 없습니다. 끝난 날짜를 적고 최신 안내로 가는 길을 덧붙이면, 그 글로 들어온 사람도 현재 정보를 찾을 수 있습니다.

### 다른 사람이 쓴 글의 틀린 정보는 어떻게 하나요?

직접 고칠 수 없으므로 공식 채널을 정확하게 유지하는 데 힘을 씁니다. 플랫폼에 정정 요청 기능이 있으면 근거를 갖춰 이용합니다.

### 소문으로 퍼진 내용에도 공지를 내야 하나요?

손님의 헛걸음으로 이어질 만한 내용이라면 정확한 사실을 공지합니다. 누가 퍼뜨렸는지를 따지기보다 현재 운영 정보를 분명히 적습니다.

### 종합광고대행사에 정정 작업을 맡길 수 있나요?

맡길 수 있지만 현재 사실을 정리한 문서는 매장에서 직접 만들어야 합니다. 무엇이 맞는지는 운영하는 쪽만 알 수 있기 때문입니다.

### 지점이 여러 곳이면 무엇을 더 챙겨야 하나요?

공지와 수정 내용마다 어느 지점의 정보인지 표시합니다. 한 지점의 변경이 다른 지점에도 적용되는 것처럼 읽히지 않게 합니다.

### 수정 전후 화면은 왜 기록해 두나요?

변경이 실제로 반영됐는지 확인하는 근거가 됩니다. 나중에 같은 문의가 들어왔을 때 어느 시점의 정보를 본 것인지 가늠하는 데에도 쓰입니다.
